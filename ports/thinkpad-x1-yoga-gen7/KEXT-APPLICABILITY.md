# X1 Yoga Gen 7 kext and driver coverage

This is a hardware-coverage audit, not a claim that any macOS driver has been runtime-tested on the Yoga. The Recovery EFI intentionally contains only the components needed for a first boot, keyboard/pointer access, and the AX211 Wi-Fi experiment. Adding every available kext to Recovery would increase boot risk without making unsupported devices work.

## What is included now

The Recovery template contains Lilu, VirtualSMC, WhateverGreen, Tahoe AirportItlwm, VoodooPS2Controller with keyboard and mouse plugins, USBToolBox with the captured Yoga `UTBMap`, and a disabled `XHCI-unsupported` entry. The recovery builder stages the pinned XHCI bundle even while disabled, so it can be re-enabled for rollback. The current USB config has boot args `-v keepsyms=1 -igfxvesa io=0x16`, without `debug=0x14e`, `cpus=1`, or `-utboff`; the Yoga map and `ProjSsdt` deletion remain enabled. Its latest OpenCore log is from Oct 29 22:38, so the Oct 30 XHCI kext A/B has no observed runtime result. The separately staged `-utbacpioff` variant changes only the boot-args string and passes OpenCore 1.0.8 `ocvalidate`; it also has not been boot-tested. Plist validation does not prove runtime compatibility.

For installation, missing touchpad, touchscreen, stylus, Bluetooth, audio, battery, camera, fingerprint, and GPU-acceleration drivers are not all prerequisites. AX211 Wi-Fi has been observed working in Recovery. The missing I2C kexts explain why the I2C touchpad and Wacom input are unavailable; they do not by themselves explain the installer restart. The USB panic files are four identical copies of one early XHCI `getAcpiPort` null-page fault. Its old boot args differ from the current USB config. The later installer restart remains unexplained because the latest OpenCore trace stops at the macOS handoff and no newer kernel panic is present.

## Primary driver references

- [USBToolBox usage](https://github.com/USBToolBox/kext#usage): `UTBDefault` is a generic codeless injector for the pre-map stage; replace it with a generated machine-specific `UTBMap` after mapping.
- [VoodooI2C HID satellite documentation](https://github.com/VoodooI2C/VoodooI2C/blob/master/Documentation/Satellites.md): `VoodooI2CHID` targets I2C-HID devices advertising `PNP0C50`.
- [WhateverXe compatibility and requirements](https://github.com/b00t0x/WhateverXe): its `46A8` backend and experimental internal-eDP support are candidates, not proof that this Yoga panel works. The project requires Tahoe 26.7 or newer and does not allow WhateverGreen to load alongside it.
